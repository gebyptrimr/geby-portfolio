05. Project Case Study

LP2M UNM – Archive Information System (SIPAS)

A web-based system for managing institutional documents and archival records.

← Back to ProjectsGitHub

01. Overview

LP2M UNM is a web-based archival information system (SIPAS) designed to manage institutional documents such as incoming and outgoing correspondence, contracts, assignments, decisions, and archive retention.

Role
Web Development Intern
Period
Jun – Aug 2026
Stack
React.js, Laravel, Supabase

Key Features

▤Document ManagementAdd and manage incoming/outgoing letters, assignments, decrees, and contracts.
▦Archive CategorizationArchives grouped by field: policy, finance, research, community service, publications, and more.
⌕Search & FilterFind an archive by number or subject; see the latest entries at a glance.
◷Retention ManagementA dedicated menu to track how long each archive must be kept.

02. Problem

LP2M handles documents from many fields at the same time: correspondence, assignment letters, decrees, and contracts, alongside research, community service (PKM), publications and IPR, finance, and general administration. Each type needs consistent handling.

  • Classification. Many categories and sub-categories have to stay consistent.
  • Findability. Staff need to locate a letter quickly by its number or subject.
  • Retention. Archives must follow a retention period instead of piling up indefinitely.

03. My Role

Web Development Intern at LP2M Universitas Negeri Makassar (Jun – Aug 2026), working on both the interface and the data side of the system.

  • Built the React interface foundation: sidebar, navbar, and routing.
  • Developed the dashboard and connected it to backend data.
  • Designed the archive classification UI/UX.
  • Designed the normalized database schema that supports retention logic.
  • Implemented document management for incoming/outgoing letters, assignment letters, decrees, and contracts.

04. Technology

FrontendReact.jsComponents, routing, dashboard UI

05. Development Process

  1. Interface & structureBuilt the layout foundation in React: sidebar, navbar, and the routing architecture.
  2. Data designDesigned a normalized database schema, including the logic behind archive retention.
  3. Dashboard integrationConnected the dashboard to backend data: archive counts, category distribution, and latest archives.
  4. Classification UXDesigned the archive classification flow and the forms for adding and managing documents.

06. Key Features

▤Document ManagementAdd and manage incoming/outgoing letters, assignments, decrees, and contracts.
▦Archive CategorizationArchives grouped by field: policy, finance, research, community service, publications, and more.
⌕Search & FilterFind an archive by number or subject; see the latest entries at a glance.
◷Retention ManagementA dedicated menu to track how long each archive must be kept.
▥Dashboard SummaryArchive counts per type and a distribution chart by category.
◉Account ManagementAdministrator account and user access in one menu.

07. Challenge & Solution

Challenge

Every document type shares a common structure but differs in category and retention period, so handling each type separately would have meant duplicated logic and inconsistent data.

Solution

Modeled archives, categories, and retention rules in a normalized schema, so retention follows from the data model rather than from separate code for each document type.

08. Result

Live dashboardCounts per document type, a distribution chart, and the latest archives in one view.
